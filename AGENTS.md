## 0x02. Policy

### Document Policy

- Rewrite documentation, do not patch it. Rework the structure and the logic as a whole. Keep the
  main flow short and easy to scan. Put the detail where it does not interrupt the reader.
- A document that contradicts the code is a defect. Fix it in the change that made it wrong.
- Write all documentation in ASD-STE100 Simplified Technical English.

### Coding Policy

- Understand the data first.  
  Before coding, understand where the data comes from, how it is transformed and used, and whether it is persisted.

- Review before implementation.  
  Start a subagent to check the proposed approach against best practices.

- Rewrite instead of patching.  
  Prefer a clean implementation over workarounds, while safely migrating persisted data.

- Preserve the design intent.  
  Let the design guide implementation choices. Never hide errors or fail silently.

- Maintain one source of truth.  
  Identify the authoritative data source and eliminate redundant state, transformations, and processing.

- Document contracts and boundaries.  
  Focus on data definitions, transformations, architecture, protocols, and module boundaries. Keep implementation details secondary.

- Make behavior observable.  
  Add structured logs at responsibility boundaries and key processing points. Without logs, issues cannot be traced or diagnosed.


## 0x03. Content Generation

When you generate content for a reader, consider the `/i-have-adhd` skill. 
Lead with the next action, number the steps, and keep each list short.

## 0x04. Before you change

Read the document that covers what you change. [docs/README.md](docs/README.md) lists them in
reading order, and [architecture.md](docs/architecture.md#the-tree) draws the tree.

| Before you | Read |
| --- | --- |
| build or run | [development.md](docs/development.md) |
| change how anything is wired or owned | [architecture.md](docs/architecture.md) |
| write Swift: naming, style, concurrency, comments | [standards.md](docs/standards.md) |
| add or restyle a view | [ui.md](docs/ui.md) |
| add a preference | [architecture.md](docs/architecture.md#settings) |
| add, move or delete a file, or change a package pin | [development.md](docs/development.md#the-project) |
| touch one feature's internals | [features/](docs/features/); each opens with its invariants |
| claim a change is done | [testing.md](docs/testing.md) |
| ship a version | [release.md](docs/release.md) |

Then read the invariants that guard the code you touch. Never break one without an explicit task to
do so.

| Invariants of | Are in |
| --- | --- |
| the platform: latest macOS only, no compatibility | [standards.md](docs/standards.md#posture) |
| the owner and the layers | [architecture.md](docs/architecture.md#one-owner), [standards.md](docs/standards.md#organization) |
| concurrency | [standards.md](docs/standards.md#concurrency-and-lifetime) |
| the look | [ui.md](docs/ui.md#invariants) |
| one feature | its document under [features/](docs/features/), section `## Invariants` |
| a Debug run, which edits the real notes and settings | [development.md](docs/development.md#debug-and-release) |

## 0x05. Before you finish

Each item is explained in [testing.md](docs/testing.md#definition-of-done).

- `./Scripts/run-tests.sh` passes.
- The Debug build compiles with zero warnings.
- `./Scripts/lint.sh` is clean.
- `grep -rln 'import AppKit\|import SwiftUI\|import Cocoa' Noto/Features/*/Model/` returns nothing.
- Each doc your change made wrong is fixed in the same change.
- Each doc sentence you added or changed obeys [Documentation language](docs/README.md#documentation-language).
- A change the user can notice has a line under `Unreleased` in `CHANGELOG.md`.
- The commit message has the form in [0x00. Importance](#0x00-importance).
